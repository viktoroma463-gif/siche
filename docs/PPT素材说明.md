# 思拆 · 最终版 PPT 素材说明

适用场合：工程心理学 / 软件设计课程展示（10–15 分钟）。  
本版为**统一版**：无高校版 / 测评版区分，所有用户拥有完整功能。  
截图：`docs/ui-shots/` 中的 **v3-01 / v3-02 / v3-03** 为当前界面；v1/v2 旧图不再使用。

建议结构：定位与问题 → 理论抓手 → 交互走查 → 草稿门与审查 → 导出与过程档案 → 技术栈 → 局限。

---

## 幻灯片映射

### 第 1 页　产品定位
- 「思拆」：学术写作认知支架智能体。
- 宗旨：先独立、后协作、再审查。
- 不是代写工具，也不是事后查重；是在写作过程中把高阶判断留在学生这边。
- 配图：`v3-01-启动封面.png`。

### 第 2 页　要解决的问题
- 本科生、研究生写课程论文、综述或调研报告时，容易把研究问题、核心观点、证据评判、结论卸载给生成式 AI。
- 理论抓手：认知卸载、机器启发式 / 自动化偏差、加工流畅性。
- 设计对策：把 AI 学术规范写成可点击、可对话、可导出的操作流程。

### 第 3 页　统一版与五个模块
- 不再区分「自发个体 / 高校测评」；一套版本，完整功能。
- 五个模块标签：确定研究问题、文献线索与检索、核心观点探讨、证据评判、论证逻辑检查。
- 不选模块 → 通用学术思辨兜底；切换模块只换视角，不清空上下文。
- 配图：`v3-02-协作区.png`。

### 第 4 页　三种 AI 消息与复制行为
- `guide`：引导、反问、角度 → 直接复制。
- `scaffold`：句式支架、局部示范 → 复制触发微测试。
- `generated_draft`：满足四项条件后的草稿 / 润色参考 → 强制微测试。
- 关键点：复制行为由后端 `content_type` 决定，不由模型自由决定。

### 第 5 页　草稿生成四项条件
1. 用户已有本人思考产出（草稿、判断、推理、取舍；多轮修改稿也算）。
2. 完成一轮思辨来回（AI 给角度，用户给自己的想法；「好的明白了」不算）。
3. 用户明确请求参考片段 / 改写 / 整理 / 润色。
4. 不是整篇论文或大章节，只允许局部片段。
- 四项同时满足才生成 `generated_draft`，开头强制警告，末尾提醒查看风险清单。

### 第 6 页　交互走查 1：闪屏与自由对话
- 3 秒闪屏：亚麻浅米色 + 居中砖红色方框「思拆」，无按钮、无表单。
- 自动进入左右分栏：左窄右宽。
- 右侧顶部五个模块标签；中部消息列表固定高度、内部滚动；底部输入框固定。
- 配图：`v3-01`、`v3-02`。

### 第 7 页　交互走查 2：分层引导
- 直接说「帮我写」→ 第一层：角度 + 反问。
- 继续说「还是不会」→ 第二层：空白句式支架。
- 第三次 → 第三层：标注【仅思路示范，禁止直接复用】的局部片段。
- 仍坚持 → 只给「缩小问题 / 保存进度退出」，并提示可以写自己的想法来换取参考草稿。

### 第 8 页　交互走查 3：复制前微测试
- 对话过程零弹窗；只有点复制才触发。
- 局限声明：认知辅助支架，不可直接粘贴；截图无法规避机制；目的是唤起自主反思。
- 80–300 字三选一：接受并微调 / 补充对立思考 / 指出适用边界。
- 不校验对错，敷衍内容原样保存导出；提交后才解锁本条复制。

### 第 9 页　左侧栏：思想留存、规划单、风险清单
- 个人思想留存区：自动保存用户全部发言，固定高度内部滚动，带时间戳。
- 研究规划单：侧边抽屉，只覆盖左侧，不遮挡右侧聊天；4 个可编辑栏目；失焦自动保存；支持从用户发言预填充。
- 风险审查清单：常驻，无需勾选；生成参考草稿时 2 秒浅砖红闪烁。
- 配图：`v3-03-研究规划单.png`。

### 第 10 页　会话导出：课程作业过程档案
- 一次导出 HTML + JSON 两份文件。
- 内容：元信息、完整对话（含 content_type）、规划单、复制与微测试事件日志、风险清单原文。
- HTML 中复制日志默认折叠；导出不含 API Key。
- 理论：过程性评价、自我调节学习、可追溯的学术主体性。

### 第 11 页　技术栈
- 前端：Vite + React 19 + TypeScript + Tailwind v4 + GSAP。
- 后端：FastAPI + Pydantic + DeepSeek `deepseek-flash`。
- Prompt：公共底层 + 模块视角 + 阶段 / 草稿许可，三层动态拼接。
- 规则：确定性状态机负责分层引导与草稿四项条件；模型只在规则放行后生成内容。
- 持久化：SQLite（会话、规划单、微测试作答）。

### 第 12 页　实施过程
- 五步：需求澄清 → 公共 Prompt 与四层规则 → 引擎与 content_type → 纸感双栏界面 + GSAP → 真实模型联调与打包。
- 一句话：「先把规范变成规则，再把规则变成界面，最后让模型只在规则内说话。」

### 第 13 页　局限与伦理
- 微测试不校验对错，只做低负荷反思；导出交由老师评估质量。
- 复制锁定只限制应用内一键复制；截图、手动选中无法物理阻止，也不记入日志。
- 文献线索一律【待核验】；DeepSeek API 不带联网搜索，不承诺实时来源。
- 不替代教师评价，也不应用来规避学校的生成式 AI 规范。
